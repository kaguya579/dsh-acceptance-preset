# 诊断专项业务描述

## 业务背景

本专项适用于车辆诊断领域（UDS / ISO 14229）的交付物验收。车端诊断软件通过统一诊断服务（UDS）与诊断仪通信：诊断仪按服务标识（SID）发起请求（如 0x22 按标识符读取数据、0x2E 写入数据、0x27 安全访问、0x14 清除故障码、0x19 读取故障码、0x31 例程控制），车端按服务响应。诊断需求通常以诊断调查表或诊断需求文档形式给出，包含每个 SID 的支持状态、DID（数据标识符）清单、DTC（诊断故障码）清单与安全等级。云端侧通常包含诊断配置与远程诊断通道。

## 检查重点

1. **UDS 协议一致性**：交付代码中实现的 SID/DID/DTC 与诊断需求一致；正响应/负响应码（NRC）处理符合 ISO 14229；安全访问（0x27）的种子-密钥流程、安全等级与会话切换的时序关系正确。
2. **诊断文档偏差**：诊断相关文档（诊断调查表、需求文档）与代码实现互相矛盾——文档声明的 SID/DID/DTC 与代码中实际实现不符，或同一数据在多个文档中口径不一。
3. **诊断需求覆盖**：诊断需求清单中的每一项（SID、DID、DTC、安全等级）在交付物中均有对应实现或明确说明；缺项或不支持状态与需求不符。
4. **通信层一致性**：诊断服务的传输层（CAN 传输协议 / DoCAN ISO 15765、DoIP）与诊断会话配置、地址映射在代码与文档间一致。

## 常见偏差

- DID 定义在代码与文档中长度/字节序不一致
- 负响应码（NRC）漏处理或错误映射（如 0x31 条件不满足时应回 NRC 0x22）
- 安全等级（如 0x27 子功能 01/03/05）与诊断需求的安全等级表不符
- 文档声明支持某 SID，代码中无对应服务函数或响应路径
- DTC 编号、故障确认/去确认逻辑与需求不符
- 会话切换（0x10）后 DID 支持状态未按需求变化
