# 云端 Java 专项业务描述

## 业务背景

本专项适用于云端 Java 服务（Spring Boot / Spring Cloud 微服务、工具库、中间件等 Maven 多模块工程）的交付物验收。云端交付物通常包含：多模块源码（`hutool-core` 式功能模块划分）、构建清单（根 pom + 模块 pom + BOM）、配置文件（application.yml/properties、bootstrap 配置）、接口/API 文档（OpenAPI、接口说明）、部署与运维文档。验收重点是：分层与包结构是否自洽、接口与文档是否一致、配置是否外部化、依赖与版本是否统一、异常与日志是否规范。

## 检查重点

1. **分层与包结构**：包/模块分层与架构文档一致；模块间依赖是否出现越层（controller 直连 dao、模块互相循环依赖）；有分层规则文件时直接引用 `architecture_facts.layering.violations` 取证。
2. **接口/API 文档一致性**：接口路径、方法、参数、响应结构与文档/OpenAPI 声明一致（文档间偏差、文档-代码偏差）；配置项名与文档/代码使用一致。
3. **配置外部化与部署说明**：硬编码配置（IP、端口、密钥、账号密码出现在代码/常量类）、环境区分（dev/prod 配置）、部署文档（启动方式、依赖中间件、环境变量清单）完整性。
4. **异常处理与日志**：吞异常（空 catch）、无日志/日志不打关键路径、敏感信息（密码/token）进日志、错误码与文档不一致。
5. **依赖与版本管理**：依赖事实（`architecture_facts.manifests` 的 pom 条目）与代码实际使用一致；版本漂移（模块间引用同一库不同版本）；版本同步（根 pom ↔ `bin/version.txt` ↔ CHANGELOG 头行三处一致——hutool 实测口径）；依赖冲突与传递依赖隐患。
6. **测试与 CI**：测试存在性与比例（src↔test 映射）、测试报告、CI 配置（构建脚本、流水线文件）完整性、测试是否真的执行（不是空壳）。

## 常见偏差

- 接口文档声明了某端点，代码中无对应 Controller/路由（文档-代码偏差）
- 分层违规：controller 直接调用 dao、service 互相循环依赖
- 版本漂移：根 pom 与模块 pom 版本不一致、CHANGELOG 未同步版本号
- 硬编码配置：数据库连接、密钥、IP 写死在代码里
- 吞异常：空 catch 块、异常无日志直接 return
- 配置项名称在文档与代码间不一致
- 依赖清单与 pom 声明不符（代码 import 了未声明的库）
- 测试文件存在但内容为空壳/未接入 CI

## 与通用验收的衔接

- 本专项叠加在通用验收之上：先按通用流程跑 acceptance_run（确定性事实），再按本文件的检查重点逐项语义判断；
- 分层校验：agent 从架构文档提取分层意图，写入本轮产物目录 `架构分层规则.json` 后重跑 acceptance_run（或传 layer_rules 参数），`layering.violations` 直接作为分层违规证据；
- 依赖/版本类检查以 `architecture_facts.manifests`（maven 条目）与 `dependencies.external` 为证据底。
