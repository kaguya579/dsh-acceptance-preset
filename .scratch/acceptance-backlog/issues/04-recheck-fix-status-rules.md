# 04 复验修复状态评估无结构化规则

Status: needs-triage

## 描述

历史 Python 工具有确定性规则 `evaluate_fix_status`（按规范化标题匹配上轮/本轮问题：未修复/部分修复/已修复/无法判定，含「偏差分析未执行时 LLM 型问题判无法判定」的防假已修复护栏）。原生版事实包只携带 `previous_issues` 与 `changes`，修复状态完全靠 agent 临场发挥，口径可能轮次间不一致。

## 建议处置

两个方向择一：a) 把确定性规则内建进插件（匹配逻辑可确定，但「本轮问题清单」来自 agent 语义层，需要 agent 把本轮问题回写进某个落盘文件才能确定性比对——引入新接口）；b) 在 systemPrompt 与 CONTEXT.md 固化 agent 侧的评估规则（匹配口径 + 无法判定护栏），保持 agent 执行但口径统一。推荐先走 b，代价小且符合 ADR-0002 分层。
