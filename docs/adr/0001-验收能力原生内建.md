# ADR-0001 验收能力原生内建，而非桥接外部工具

- 状态：已接受（2026-08-16）
- 相关：ADR-0002（确定性/语义分层）、ADR-0003（路径语义）

## 背景

初版 DSH 插件以「桥接」方式工作：通过 subprocess 调用外部 Python 交付验收工具（project-handover）的 `facts` 出口，再读回 JSON 事实包。该方案的问题：

1. **外部依赖**：要求 Python ≥ 3.12、`.venv`、`pip install -e .`——分发与部署都要携带整套外部工程；
2. **沙箱冲突**：DSH Windows 沙箱下受限子进程无法写工作区（实测 Errno 13），迫使验收运行使用 `danger-full-access` 策略，破坏沙箱边界；
3. **生命周期割裂**：插件与外部工具两个仓库两套演进节奏，能力升级要改两边。

## 决策

**确定性验收能力（安全解包、文档解析、tree-sitter 静态分析、补缺识别、轮次快照）原生内建在插件中**（纯 Node + WASM 依赖，零外部进程），产物落盘走 harness `fs` 服务。外部 Python 工具归档（zip 备份 + GitCode `archived` 标签），其领域文档由本工程继承整理。

## 后果

- 零外部进程：解析在 harness 进程内完成，遵守会话沙箱策略，不需要任何提权；
- 依赖树自含：npm 纯 JS/WASM 依赖（fflate/tar-stream/mammoth/pdfjs-dist/xlsx/web-tree-sitter/tree-sitter-wasms），无原生编译；
- 代价一：需维护 `lib/` 各解析模块；部分解析能力弱于原工具（docx/pdf 章节层级、docx 基线列表的 numPr 语义），见 backlog；
- 代价二：tree-sitter-wasms 全量 51MB 仅使用 6 个语言，依赖体积偏大，后续可按需裁剪。

## 替代方案（已弃）

- **桥接 CLI**（已实现并弃用）：见背景问题清单；
- **纯零依赖实现**：pdf/docx 的可靠解析无法零依赖完成（docx 是 zip+XML 尚可手写，pdf 不可行），弃。
