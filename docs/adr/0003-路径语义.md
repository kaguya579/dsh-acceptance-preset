# ADR-0003 路径语义：验收目录由用户提供，产物随交付物同级

- 状态：已接受（2026-08-16，2026-08-16 修订）
- 相关：ADR-0001（原生内建）

## 背景

初版把 `projectRoot`/`outDir` 固化在 preset 组合的 `config` 中，指向特定机器路径。开源分发后这些路径对他人无意义；且把「交付物目录」与「需求/合同目录」混进一个 projectRoot 相对基准，与甲方实际使用方式（两个独立来源）不符。

## 决策

1. **交付物目录**（供应商交付）与**需求/合同目录**（甲方基线，可选）是两个独立来源，**验收时由用户分别提供**（绝对路径）；插件不预设任何固定数据根目录；
2. **验收产物放交付物同级**：产物根缺省为 `<交付物父目录>\acceptance`；用户可指定任意目录（工具参数 `out_dir`，`config.outDir` 全局覆盖）；插件工程内的 `acceptance/` 仅保留为历史产物，作为读/列工具的缺省回落位置；
3. 组合配置**零必填**；agent 在验收前向用户询问两个目录（产物目录可选）。

## 后果

- 插件开箱即用，无机器相关配置；
- 产物与交付物数据同处一地：交付物目录移动/归档时产物跟随可见；跨轮复验依赖产物留在原位；
- agent 每次验收需与用户确认目录路径（多一次交互，换取零配置与来源清晰）。

## 修订记录

- 2026-08-16（v0.5.0）：产物位置语义修订——**由「随插件工程」改为「交付物同级」**（`<交付物父目录>\acceptance`），并支持用户指定目录（工具参数 `out_dir`；`config.outDir` 全局覆盖）。原「随插件工程」方案的问题：产物藏在 `.agent-presets` 下难以发现与归档。
