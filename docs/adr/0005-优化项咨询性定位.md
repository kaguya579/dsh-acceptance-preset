# ADR-0005 优化项定位：咨询性内容，不影响验收结论

- 状态：已接受（2026-08-16）
- 相关：ADR-0002（确定性/语义分层）、ADR-0004（架构事实扩展）

## 背景

验收报告只有缺陷视角，甲方接手时缺少「哪里不合理、怎么优化」的视角。但「不合理之处」与「偏差」性质不同：偏差有基线/文档可证，不合理之处是度量与主观判断的混合；若把主观判断混入验收判定，供应商一句「合同没要求」即可引发争议，且取证标准无法公平。

## 决策

1. **验收报告新增「架构与质量评审」节**：架构梳理（依赖图/模块边界观察）→ 优化项清单（按高/中/低分组，每条=证据〔文件:行号+度量数字〕+判断+建议）→ 与接手方案的衔接；与业务画像分工——画像说「是什么」，评审节说「哪里不合理、怎么优化」；
2. **优化项为咨询性内容**：不影响验收结论（通过/打回/无法判定）、不进整改清单、不参与问题分级；分级沿用新术语「高/中/低」，与「问题分级（阻断/严重/一般）」彻底分开；风格类主观项（命名、风格、重构品味）不列入优化项；
3. 优化项的证据锚定在确定性层架构事实上（ADR-0004），评分/阈值裁量归 agent 语义层。

## 后果

- 供应商合规交付不会被主观判断打回，争议面小；甲方获得接手/维护视角；
- 评审节质量取决于 agent 取证是否落到具体证据，系统提示与 CONTEXT.md 固化检查口径；
- 复验时架构趋势靠 agent 现场对比两轮事实包，可能漏比——可接受，后续可内建（见 backlog）。

## 替代方案（已弃）

- **独立「架构评审报告」产物**：与验收结论完全解耦、可单独交付，但多一套产物与读取流程，且与验收报告割裂；
- **参与验收判定（可致打回）**：新增「架构不合理」偏差类别。甲方约束力最强，但判定主观、取证标准难以公平，易与供应商产生争议；
- **插件侧轮次对比**：趋势稳定可复现，但首刀工期与 schema 兼容成本不划算，暂缓。
