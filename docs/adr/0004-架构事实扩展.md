# ADR-0004 架构事实扩展：统一 tree-sitter 提取，不引外部图引擎

- 状态：已接受（2026-08-16）
- 相关：ADR-0001（原生内建）、ADR-0002（确定性/语义分层）

## 背景

验收报告只有缺陷视角（四类偏差 + 问题分级），甲方接手时缺少「架构梳理、不合理之处、优化方案」的视角。调研同类产品（SonarQube、CodeScene、NDepend、ArchUnit、deptrac、Thoughtworks 适应度函数、codegraph 类引擎等）后确认：依赖图、耦合/复杂度度量、依赖清单是这类能力公认的确定性底座，而「是否不合理、如何优化」是语义判断。

## 决策

1. **依赖图、复杂度度量、依赖清单、重复片段由本插件统一实现**：基于现有 tree-sitter 语法树与 JSON/XML 解析栈，覆盖 6 语言（C/C++/Java/JS/TS/TSX）+ 三个构建清单（package.json / pom.xml / CMakeLists.txt）；输出进入事实包（schema 升版 `acceptance-facts/2` 新增「架构事实」节），只产事实、不产结论；
2. **不引外部图引擎**（Netflix CodeGraph、Sourcegraph SCIP、ArchGuard 等独立进程，违背 ADR-0001 的零外部进程、不执行交付代码、纯 Node/WASM 约束，且多数要求 git 仓库）；**不混搭 JS 专用库**（dependency-cruiser、madge 仅覆盖 JS 系，双引擎维护成本高于自研收益）；
3. **规则语义借鉴而不引入**：依赖环、孤儿模块、可达性、分层违规等检查项参考 dependency-cruiser/ArchUnit/deptrac 的规则语义，由 agent 按需求与基线临场裁剪写进语义层检查清单，不把规则固化进插件（延续 ADR-0002 分层）；
4. **跨轮次架构趋势由 agent 对比两轮事实包完成**（新增/消失依赖环、复杂度增减、依赖增删），插件不做轮次间 diff。

## 后果

- 单一 tree-sitter 管线，维护面小；不新增语言时 wasm 体积不变；
- 每种语言的 import 解析规则自行维护，解析质量上限受限于语法级分析（不做类型级/符号解析），未解析引用进 unresolved 清单；
- facts schema 出现 /1 与 /2 两版并存：新轮次产 /2，历史轮次保持可读（read 工具按 schema 版本分派）。

## 替代方案（已弃）

- **引入 codegraph 类外部引擎**：违反 ADR-0001 与沙箱约束，且交付物是 zip/目录快照、无 git 历史，前提不成立；
- **混搭 dependency-cruiser/madge**：JS/TS 省事，但 C/C++/Java 仍需自研，两套引擎并存的解析口径与维护成本反而更高；
- **第一刀带测试映射/新语言**：测试映射启发式误报率高、新语言推高 wasm 体积，均推至第二刀。
